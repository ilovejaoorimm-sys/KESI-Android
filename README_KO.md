# KESI Android 3.0 — 원격 지표 업데이트

앱을 재설치하지 않고 지표 목록·수치·가중치·선형 점수 구간을 반영하는 버전.
**현재 GitHub 배포는 인증 문제로 미완료다. 아래는 구현된 구조이며, 원격 서비스가 가동 중이라는 뜻이 아니다.**
APK 설치 후 원격 파일이 아직 없으면 기존 6개 지표 구성을 사용하여 5개 공식 통계를 직접 수집한다. PF는 미수집이다.

## 구조
- `config/indicators.json`: 지표 목록, 공식 계열, 가중치, 점수 구간, 유효기간. 현재 6개.
- `backend/collect.py`: 공식 ECOS API에서 원자료를 수집하고 동일 기간·단위를 검증. 실패한 값은 null.
- `.github/workflows/refresh-data.yml`: 6시간마다 및 설정 변경 시 자동수집 → `data/feed.json` 갱신.
- `data/feed.json`: 실제 수집 결과. APK에 내장하지 않는다.
- Android 앱: 고정된 사용자 저장소의 HTTPS feed를 조회, 검증한 뒤 목록·카드·위젯·점수에 반영.
- `.github/workflows/build.yml`: 앱 소스 변경 시 테스트·lint·APK 서명 검증 후 빌드 산출물 업로드.

원격 URL: https://raw.githubusercontent.com/ilovejaoorimm-sys/KESI-Android/main/data/feed.json
앱과 서버가 각각 약 6시간 간격으로 갱신하므로 반영에 최대 약 12시간+스케줄 지연이 생길 수 있다. 앱의 새로고침은 최신 서버 파일을 즉시 확인한다.
GitHub의 스케줄 실행은 정시를 보장하지 않으며, 공개 저장소가 장기간 비활성 상태이면 스케줄 워크플로가 중지될 수 있다. GitHub Actions 상태를 확인해야 한다.

## 새 지표 추가 — APK 재설치 불필요한 범위
1. 공식 API에서 표 코드·항목·단위·기간 정의를 확인한다. 단순히 이름이 비슷한 계열을 대신 사용하지 않는다.
2. `config/indicators.json`의 `indicators` 배열에 새 객체를 추가한다. 고유 id와 이름, 단위, 데이터 출처, 점수 구간을 지정한다.
3. 새 지표는 기본적으로 `weight: 0`으로 둔다. 이 경우 참고용이며 종합점수·스트레스 가산점에 영향을 주지 않는다.
4. 종합점수에 반영하려면 모든 양수 가중치 합을 정확히 1로 조정한다. 임의 재정규화는 하지 않는다.
5. `revision`을 증가시키고 계산 정의가 바뀌면 `method`도 바꾼다.
6. 변경을 main에 반영하면 통계 수집 워크플로가 동작한다. 성공한 feed를 앱이 읽으면 새 지표가 표시된다.

지원 수집 형식: ECOS 월별/일별 원자료, 월별 전년비(`yoy`), 동일 주기·동일 날짜 두 계열의 차이(`spread`).
미지원 출처는 `unavailable`로 명시한다. 새로운 기관은 서버 수집기를 추가해 같은 feed 형식으로 내보내면 된다. 공식 출처 검증을 완료하기 전에는 수집 완료로 표시하면 안 된다.
지원 점수 형식: 상향/하향 선형 0~100점, 가중합, 기존 스트레스 가산점.
임의 함수·실행 코드·APK 자체의 자동 설치는 지원하지 않는다. 새로운 계산 방식·화면 기능은 앱 업데이트가 필요하다. 최대 지표 수는 40개다.

## 결측·오류 처리
- 기본 PF 연결 미확인: 값 없음, 미수집. 기본 가중치가 15%이므로 종합점수와 위험등급은 판정 보류.
- 결측을 0으로 채우거나 샘플 데이터로 대체하지 않는다.
- 기준기간·발표일·수집시각은 별도 필드. ECOS가 제공하지 않는 발표일은 null/미확인.
- 원격 문법·버전·고유 ID·가중치 합·유한 수치·기간·출처 HTTPS 주소를 검증한다.
- 현재값과 3개월 전 값은 같은 설정으로 계산한다. 과거 당시 공개 정보의 백테스트가 아니다.
- 잘못된/이전 버전의 원격 파일은 저장하지 않는다. 직전 정상 파일은 보관하되 갱신 실패 시 종합 판정을 보류한다.
- 서버 생성 후 48시간을 넘은 feed 및 지표별 유효기간 초과 관측값은 종합 산출에서 제외한다.
- 원격 파일을 한 번도 받은 적이 없으면 앱의 내장 공식 수집기를 사용한다. 원격 연결 상태를 화면에 표시한다.

## 최초 배포
1. 이 프로젝트 **내용**을 `ilovejaoorimm-sys/KESI-Android`의 main 루트에 올린다. `.github/workflows`도 포함해야 한다.
2. Actions의 `Build and verify KESI APK` 및 `Refresh official statistics` 실행을 확인한다.
3. 저장소 정책상 `contents: write`가 허용되어야 통계 수집 워크플로가 `data/feed.json`을 커밋할 수 있다. 제한되어 있으면 해당 작업은 실패하며 권한을 우회하지 않는다.
4. 공개 raw feed가 정상 JSON을 반환하는지 확인한다. 앱에서 새로고침 후 ‘원격 지표 자동 반영’ 및 설정 버전을 확인한다.
5. 새 지표를 weight 0으로 추가하여 앱 재설치 없이 카드가 추가되는지 확인한다.

API 인증키나 개인 토큰은 코드에 넣지 않는다. 수집기는 ECOS 공개 제한 접근으로 페이지당 10행 한도를 지킨다. `sample`은 API 접근 문자열이며 샘플 수치가 아니다.
개인 설치용 debug APK는 빌드 환경마다 서명이 달라질 수 있다. 지속적인 APK 덮어쓰기 업데이트에는 동일한 비공개 서명 키를 보관하고 GitHub Secrets로 연결하는 별도 배포 설정이 필요하다. 키를 공개 저장소에 커밋하지 않는다.

## 로컬 검증
```sh
python3 -m unittest discover -s backend -p 'test_*.py'
python3 backend/collect.py
gradle :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```
JDK 17 / Gradle 8.9 / AGP 8.7.3 / compile SDK 35, Android 8.0 이상.
기존 지표 정의·가중치·휴리스틱의 한계는 `docs/V2_METHOD.md`, 최신 검증 상태는 `docs/VALIDATION_V3.md` 참조.
